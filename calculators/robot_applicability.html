Robot Applicability Scorer

Pre-loaded with customer data - scores each SKU category for Locus Origin and Array + NeuraGrasp fit using defined criteria

What this calculator does: Evaluates each product category against the operating profile of each Locus robot using weighted criteria. Scores are derived from specific, observable characteristics - not subjective judgment - so an SE can explain the recommendation to a customer and adjust the weights for unusual scenarios.

Key output: H&B routes to Array + NeuraGrasp (72% of pick volume, uniform rigid items, NeuraGrasp-suitable). Apparel routes to Origin + human collaboration (non-uniform items requiring human dexterity). This category routing decision drives the phased deployment plan - one starting point, two expansion paths depending on how far the customer wants to go.

category, sub_category, unit_weight_lbs, packaging type → drives NeuraGrasp graspability and uniformity scoring
Input 2

picks per category per day → determines how much volume each robot program captures and ROI magnitude
Input 3
Inventory Snapshot - Aisle Segregation
whether category has dedicated aisles → affects deployment complexity and robot zone assignment clarity
Input 4 - SE Assessment
Packaging Uniformity
SE observes or photographs product packaging in the facility → key determinant for NeuraGrasp confidence score
Input 5 - SE Assessment
Pick Complexity
does the pick require human judgment (size selection, folding, condition check)? → affects human dexterity score for Origin vs. Array routing
Input 6 - SE Assumption
Extended Hours Value
does the category have enough daily volume to benefit from Array's 22-hr operating window? → categories with <2,000 picks/day see diminished Array ROI

Why Apparel does not route to Array: NeuraGrasp is designed for uniform rigid-packaged items. Folded apparel, hanging garments, and multi-size SKUs require human dexterity for consistent pick quality. Origin handles the travel problem while the human handles item manipulation - the right division of labor for this category.

Future Calculator Work

Items identified for future development to improve scoring precision and broaden the tool's applicability across customer scenarios.

1 - Dimension and Weight Scoring from SKU Master

The current scoring uses category-level packaging assessments made during the SE site visit. A more precise version would pull unit_weight_lbs, unit_length_in, unit_width_in, and unit_height_in directly from the SKU master and score NeuraGrasp confidence at the individual SKU level based on known arm reach, gripper size, and weight capacity specifications. This would surface SKUs within a "good" category that are actually poor Array candidates - and vice versa.

2 - Manual SE Tuning for Singular Robot Focus

Some deployment scenarios call for focusing on a single robot type for reasons outside the scoring model - customer budget constraints, a desire to start with the lowest-change deployment first, a specific labor reduction target that only one robot type meets, or a site condition (ceiling height, aisle width, fire suppression) that rules one out. An SE override panel would allow the SE to lock a category to a specific robot program and recalculate fleet sizing and ROI for that constrained scenario without re-running the full scoring model.
